metaProbiotics复现流程、学习心得与踩坑记录

前言

blog内容说明

此blog中的全部操作均基于师兄的开源仓库 metaProbiotics进行。

此blog中所有操作基于windows11系统进行。

重点专注于基于该仓库中的metaProbiotics流程复现与作为新手在复现流程中会遇到的问题（主要是我遇见的问题）以及解决方案总结；关于模型算法逻辑、论文解读相关的内容几乎为0（当然我后续将持续学习这方面的内容，blog也会更新相关内容）。

此外，这也是我第一次写blog，如果有什么问题或不足的话，欢迎大家提出并指正。

复现流程说明

基于师兄给的仓库中的说明，可将复现流程简化为“下载基因组数据并保存为.fasta文件 → 将基因组数据.fasta文件放入词向量训练代码中得到训练好的词向量模型 → 使用编码脚本读取训练好的词向量模型，将.fasta文件编码成分类代码可读的.npy文件 → 将编码后的.npy文件放入分类代码中训练得到分类模型 → 将分类模型放入预测代码中进行预测比对”。

即：
1.下载数据（通过下载脚本）：（得到.fasta）

2.训练词向量模型（通过Word2Vec）：（.fasta → Word2Vec）

3.编码（通过编码脚本）：（.fasta + Word2Vec → .npy）

4.训练分类模型（通过1D_CNN_3Conv）：（.npy + 标签 → CNN）

5.预测（通过predict）：（新 .fasta + Word2Vec + CNN → 结果）

在仓库中给出了两个词向量训练代码（Word2Vec与DNA-level BERT）: Mul_train_word2vec.py、bert_train.py和两个分类训练代码（一维卷积与卷积 + Transformer）: 1D_CNN_3Conv.py、CNN_Transf.py

在我的复现流程中，选择的是”Word2Vec”与”1D_CNN_3Conv”。

具体复现过程、出现问题与解决方案

环境配置

作为生物信息学新手，首先在流程开始前，要先配置好相关的python运行环境（我一开始装gemsim库的时候用的是python3.14，结果不兼容，没法装）。

如果你之前未安装过python，那么可以直接点击python3.10.11下载python3.10.11来兼容gemsim库。
如果你之前安装过其他版本的python（如果你之前安装的 Python 版本不在 3.8 到 3.12 之间），则需要下载3.8-3.12的python版本（这里仍然推荐python3.10.11，因为我接下来会以python3.10.11为例进行环境配置）。

安装好新的python后，可打开CMD终端输入

python --version

若出现

Python 3.10.11

则说明安装正常

为了隔离依赖，使不同项目所需要的python版本不相互干扰，我们需要在项目根目录下（在这里可以放在储存这个仓库的所有文件的总文件夹model-master中）配置虚拟的python3.10.11运行环境。

· 首先进入项目根目录，在CMD终端输入

D:
cd .\model-master

· 在根目录下创建虚拟环境，在同一个CMD终端中输入

py -3.10 -m venv venv

· 接下来激活虚拟环境，在根目录路径下，在终端输入

venv\Scripts\activate

即可在当前项目根目录下激活python3.10虚拟环境，后续的所有操作也均需基于激活该虚拟环境进行。

接下来在该虚拟环境中安装项目依赖。
· 打开新终端，输入

D:
cd {项目根目录路径}
venv\Scripts\activate

· 检查pip版本

pip --version

· 若显示版本不为25.x，则建议输入以下指令升级

python -m pip install --upgrade pip

· 接下来安装核心依赖，即在复现流程中需要用到的库，在终端输入

pip install gensim biopython numpy pandas torch scikit-learn transformers tqdm matplotlib seaborn

· 要验证这些库是否可在虚拟环境下正常导入，可在当前虚拟环境中逐行输入

python
import gensim
import Bio
import numpy
import pandas
import torch
import sklearn
import transformers
import tqdm
import matplotlib
import seaborn
print("全部导入成功！")

若每一行都不报错（No module named），则说明pip install的所有库都已经正确安装在当前的虚拟环境中。

虽然我的脚本都是直接在终端里运行，但在这里还是写一下怎么在VS Code解释器里配置虚拟环境。

· 在VS Code中打开当前项目的根目录

· 按Ctrl+Shift+P，输入Python: Select Interpreter。

· 在列表中选择路径含venv\Scripts\python.exe或含('venv': venv)的选项

· 确认VS Code右下角的状态栏中有 3.10.11 (venv)或(venv) 3.10.11

· 在当前根目录文件夹中新建python文件，输入import gensim，若不会出现黄色波浪线，则说明虚拟环境配置成功。

下载数据

环境配置好之后就要先下载数据了。

仓库中给出了要下载的数据表格，下载脚本要读取S1表格的Accessions列的文本数据，所以需要把这一列的数据保存为一个.txt文件，我这里直接给出我自己保存好的.txt文件：S1_accessions.txt，其中包含707个基因数据。

这里是仓库中的下载脚本代码Down_data.py，其原理就是读取本地保存的文本列表，然后按列表里的基因名称从NCBI数据库服务器下载到本地文件夹并保存为.fasta文件。

在下载数据之前，需要说明的是，由于NCBI服务器在海外，所以下载基因组数据时如果不挂VPN的话，很有可能要下载30小时左右，因此推荐在运行代码前先在后台挂上VPN，并且注册一个NCBI账号，这两个我在这就不做过多步骤说明了。

因为仓库中的下载脚本每次启动都是重新从第一个数据开始下载（不管这个数据是否已经下载好了），而就算挂了VPN下载时长一般也在几个小时，难免会出现程序崩溃或者需要关停脚本的情况，这时候如果重新运行下载脚本的话，又需要重新下，很耗时间，所以我自己改了下代码，让已经下载好的数据直接被跳过，不会下载第二遍；另外，S1表里有很多NZ_开头的数据，仓库里的下载脚本会忽略这些数据，所以我对索引逻辑也做了修改。

修改后的代码在这里：My_Down_data.py，把自己的邮箱和NCBI密钥填进去，然后输入数据要保存的文件夹路径就好了。

词向量训练

数据下载好之后要进行词向量训练。

这里以我复现时使用的Word2Vec为例进行说明。

首先给出训练代码：Mul_train_word2vec.py
这个训练代码只要填写一下下载数据保存的文件夹路径就好。

但是！！！
我的训练代码运行到一半程序崩溃了，显示我的内存爆了。
因为我用的是办公本，运存只有16GB，所以我又改了下代码，写了一个生成器，让代码不至于一下给我塞一坨大的，又把我的内存撑爆了。
如果你电脑运存也不是很大的话，修改后的代码在这：My_Mul_train_word2vec.py

我的电脑训练词向量花了大概三到四小时，如果你感觉代码跑得慢的话可以按Crtl+Shift+Esc打开任务管理器查看内存占用情况，把没必要的后台进程全关了。

如果你选择k=6训练256维的词向量（也就是说你对代码里除文件路径之外的参数没有任何改动）的话，词向量训练脚本运行结束后你会获得一个 .txt的日志文件 和一个 word2vec_6mer_model_256的模型文件。

词向量编码

接下来要依赖训练得到的词向量模型文件把原始的.fasta基因数据编码成.npy文件。
在这一步，仓库其实已经给了已经编码好的数据集了，如果要使用仓库里的编码数据集，其实就可以直接跳到下一步了。

但是我想自己把编码这个流程也走一遍，所以用AI辅助写了一个编码脚本：My_encode_genomes.py。

接下来是准备编码的标签文件，我用来编码的原始数据就是S1表里的那707个数据，所以把那707个数据的Accessions列和Labels列保存为.txt文件就能被编码脚本识别读取了（注意每行的Accession和Label要用空格隔开），这里也直接给出保存好的.txt文件：s1_accessions_labels.txt

最后可以得到数据集My_CNN_3Conv_6mer_256_Dataset.zip

不过我训练得到的数据集文件大小要比师兄仓库里给的数据集文件小很多，应该是因为他用的数据不止S1表里的数据。

训练分类模型

仓库里已经给了完整的训练模型，不过我这里也再给一遍我调好参数的训练模型My_CNN_3Conv.py

这里没什么好说的，把路径参数改一下就没问题了。

训练好之后你同样会得到一个.txt的日志文件和一个CNN_3Conv_Word2vec_6模型文件。

预测

终于到最后一步，也就是测试训练好的分类模型文件了。

仓库里已经有现成的预测代码：predict.py
