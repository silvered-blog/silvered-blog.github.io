关于算法的个人思考与学习路径规划

前言

最近我在思考如何适配自己的思维方式，系统性地规划一下自己的算法学习路径。

因此，有了这篇文我个人基于自身当下对算法的粗浅了解与印象，所做出的对于算法逻辑的大致的、个人化的解释，与基于当下这些粗浅了解、从而对自身后续要学习哪些算法相关的逻辑、以一种怎样的学习路径学习算法、预备通过哪些参考书进行学习的的问题进行解答的 blog 。

我个人现在对于算法的、逻辑上的印象

当我在用算法解决计算问题的时候，我时常会产生这样一种直觉——各种算法逻辑所构成的这个整体本身，似乎能够被抽象一个逻辑体系的对象来进行研究，从而跳出“特定类型问题与特定类型算法一一对应”的、使用算法的模式。

顺着这种直觉继续思考下去，我第二时间能直觉到的是，某些算法本质上就是在对信息进行操作，是将未知信息处理为已知信息并进行输出，倘若能够为算法本质上是对信息进行了何种操作、这种操作本质上对信息造成了何种影响这些问题建构一个完整的理论解释体系，那么似乎算法问题也被解决了很大一部分了。
其实这些直觉出现之后，信息论这个名词立马就出现在我的脑中了。

于是，我暂时将“信息论”视为：“有待建立初始印象的概念”和“有待列入算法学习路径的理论体系”。

其次，在上学期刚开始学习C语言的时候，我也在思考几个自然而然的问题：是否任意问题都可通过有限次的顺序结构、分支结构与循环结构解决？倘若答案是否，那么计算机可处理问题的边界在哪里？即，那些问题是可计算的？
这些问题我通过AI得知，同样有着完整的对上述问题的解答理论：计算理论。
而我当下对计算理论的了解，也仅限于图灵机。

因此，我同样也暂时将“计算理论”视为：“有待建立初始印象的概念”和“有待列入算法学习路径的理论体系”。

我当下关于信息论的一点粗浅的感性了解

既然要讲我对“信息论”的碎片话认识的话，那就从我现在了解了一点的几个信息论范畴的概念开始讲起吧。

· 比特(Bit)
在信息论理论中，使用比特(Bit)这个抽象概念来量化信息量。
尽管我暂时对于这种量化过程是如何定义的，但很容易就能直觉到：比特的定义使信息可以借助数学工具，解析为确定的、可被认知的规律，甚至可能能够对其进行公理化。
甚至于，同样可以直觉到的一点是，既然物理世界中的“信息”可被抽象为量化的“比特”，那么信息论甚至可以联系到物理理论；进一步来讲，和生物学领域产生联系也是有可能的。

· 自信息(Self-Information)
自信息在定义上，指的是单个具体事件发生所携带的信息量，其公式为：I(x) = -log2(P(x))，其中P(x)为事件x发生的概率。
尽管我不太能从公式上直观地理解其是如何将事件发生概率与信息量建立起联系的，但自信息的定义无疑将事件所含的信息量化了。

· 香农熵(Shannon Entropy)
香农熵是用来衡量整个事件系统的整体信息量的概念，其本身通常被用来判断整个随机变量平均的不确定性。
其计算公式为H(x) = -Σ P(x) * log2(P(x))，单从公式上我觉得还是挺容易理解的。

信息论本身在算法方面的应用，应该就在于分析算法的每一步操作在逻辑上在多大程度上消除了计算机存储信息的不确定性，从而以不同于算法复杂度的、信息量的角度来解释算法的优劣。

我当下关于计算理论的一点粗浅的感性了解

类似地，要讲计算理论，我也就随便讲讲我现在对图灵机的一丁点碎片化认识吧。

· 图灵机(Turing Machine)
我稍微查了下资料，我所理解的图灵机在计算理论中实际上来源于高度抽象的自动机(Automatic Machine)。
自动机来源于图灵对于计算过程的高度抽象化模型，他将任意的可被精确描述的计算过程简化为以下四种操作：

  1. 在纸上读取一个符号
  2. 根据当前的符号，依据某种规则，决定下一步要做什么
  3. 在纸上写下一个新符号
  4. 将目光移向下一个位置；而该位置可能是空的，也有可能是一个新的符号

而能够执行以上四种操作的机器，被称为图灵机(Turing Machine)。
同样地，为了实现自动机的四种操作，图灵机需要以下四种核心部件：

  1. 一条无限长的纸带(Tape): 被划分为一个个格子，每个格子被用来储存单一的、来自有限内容的单一信息
  2. 一个读写头(Head): 读取当前格的信息
  3. 一个状态寄存器(State Register): 我不太能理解这个概念，可能原因在于我不知到其物理层面是如何是实现的。只讲功能的话，其基础功能为“状态寄存器保存图灵机当前所处的状态，这个状态记录了机器在当前时刻的”处境”，是控制规则做决策的关键依据之一。”
  4. 一套有限规则表(Transition Function Table): 即图灵机依据怎样的规则修改纸带上的内容/信息。

我对这方面的了解就仅在于此了，但是我对其有强烈的探知欲望，每当我思考算法逻辑时，我都不可避免地去思考这些计算逻辑。

基于上述了解整合的学习路径与参考书

我当下对算法的认知就是：以计算理论为本质、信息论为基础、数理逻辑为操作的耦合产物。

另外，如果要学习算法本质的话，我可能会不可避免地通过对计算机底层的逻辑进行学习，因此我可能不得不重新学习C语言。

基于以上当下我对算法的有限认识，我梳理出以下学习路径：

  1. 重拾 C 语言学习，接触计算机底层逻辑
  2. 浅读《计算理论导论 第三版》，对计算原理有一定了解
  3. 浅读《信息论基础 第二版》，对算法步骤中对信息处理的原理有一定了解
  4. 学习数据结构等

尾声

随便聊聊

怎么说呢，感觉计算机这一块如果要学的话，感觉可以学地很深，是那种掉进去就出不来的深😂。
结合我自己的专业的话，尤其是现在没有核心专业课的情况下，我认为是打基础的好时机。

而且，比较愁人的一点是，我现在习惯性地用写 Python 的思维去学算法，但 Python 本身的高抽象性导致我不太能直观地感受到算法本身的逻辑。 Python 的大量操作都是建立在基础的存储操作之上的，各种操作的底层逻辑高度耦合，不太有利于我学习算法。比较直观一点的例子就是，Python中对列表的排序只需要一个list.sort()，但是我无法直接从这行代码的字面上判断其时间复杂度，只能通过解析它的 C 编译来分析。

那就先这样吧，先这么学着试试，有什么问题后面再调整。
